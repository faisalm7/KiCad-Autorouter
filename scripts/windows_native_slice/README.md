# Experimental Windows capability probe

This manual CI-only prototype is **not Windows product support**. It uses a standard Windows2022 runner, pinned official KiCad10.0.7 installer and Freerouting2.5 JAR, and an owned six-component fixture. No Mac application or global Mac settings are changed. The controller never sets accepted/passed/product_support true. A successful command only observes its owned Native capability sequence.

`bootstrap.ps1` verifies immutable download bytes and Authenticode before ordinary ephemeral installation. Registry/shortcut side effects on that runner are expected; this is not portable extraction. Missing matching bundled Python/CLI, an owned hash-pinned official Temurin25.0.2+10JRE, enabled firewall or exact live deny rules refuses Native work. Global firewall profiles are never enabled/disabled. No artifacts or caches are uploaded. Exact owned candidate/Native/transport/log payloads are bounded and retained in CI logs before scratch cleanup.

`windows_process.py` launches suspended, assigns a kill-on-close/no-breakaway2GiB Job Object, then resumes. Complete job CPU includes exited members. Final limits are checked even after the last process exits; cancellation/timeout kills the owned job and requires zero members. The CreateFile read-sharing-only guard protects source/PRL identity and bytes. These are unqualified adapters until real Windows controls run; unit controls on Mac cannot establish Windows guarantees. They are not used by the current Mac product.

`slice.py` reuses pure existing adapter/parser/factories and isolated Native netclass observation. It requires actual DSN→Freerouting→fixed-placement SES→route-only original-shell merge, nonempty Native zone fill, full original/final schematic-parity DRC, protected KEEP, one deliberately disconnected negative and cancellation of a live fresh-output engine. It emits a separate owned candidate. Scope remains partial: no graphical/review-export integration, broad input support, hostile-code sandbox, complete outer/PowerShell CPU qualification or released Windows package. Program firewall rules do not establish network denial for arbitrary differently named descendant executables; this probe uses trusted fixed owned tools/fixture only.

The original bounded source proposal/pins/review remain in the durable local evidence. Lead integration adds exact owned firewall-rule gates, final-bound checks, cancellation130 and complete owned proof/log projection. The Mac production runtime is unchanged. [Portability assessment](../../docs/windows-portability.md) lists the remaining product adapters. Dispatch only the `windows-native` input of the manual workflow after independently verifying public standard-runner zero cost and repository permission. No public package/tag/release is authorized by this workflow.
