# Required static audit after acquisition (unexecuted procedure)

Run only after the lead announces a completed immutable acquisition receipt. No native process, rendering tool, dataset script or dependency fetch is part of this procedure. All three planned projects remain in the considered population even if acquisition, closure, licensing or compatibility fails. Acquisition receipts and this report cannot establish independent board families.

1. Independently hash all existing baseline files and all newly acquired files. Compare the acquired 33-file census, Git blob identities, sizes and SHA256s to the canonical receipt/protocol. Pin that receipt, helper commit, protocol and before-inventory. Preserve any failed request or incomplete project. Enumerate every actual `.kicad_pcb`, matched `.kicad_pro` or legacy `.pro`, schematic, rules file and local table; do not infer board count from repository count.
2. Read each original LICENSE/README, every relevant native-file header, local library/model declaration and asset notice without executing it. Record author/source/license by file or explicit homogeneous group. For the Ideal Diode assembly STEP, inspect its header's originating-system/author/organization/schema and any embedded third-party notices; the root CC-BY-SA grant alone does not resolve a third-party asset exception. Inspect Apache/attribution statements in OLIMEX sources and separately account for its generated fabrication/BOM files. No payload redistribution until an explicit rights audit supports it. Missing notice is not proof of a permissive license.
3. Parse original board/project/schematic syntax read-only with bounded input reads. Record original format, copper layer names/types/count, net and terminal census, custom pads, netclasses/bindings, zones/placement/keepout flags, protected tracks, board edges/cutouts, custom rules, severities/exclusions and original source intent. Use current preflight only as an observation; do not change its allowlist to admit a new board. Legacy `.pro` and native migration stay separate gates. Report unsupported and parse-failed fields rather than guessing defaults.
4. Resolve every project-relative footprint/symbol/model/rules/schematic reference against the exact acquired tree. Keep URI text and path case unchanged. Separately classify cached symbol definitions/embedded board pads versus an authentic complete external library closure. An embedded footprint does not supply its 3D model, all stock libraries, or a historical version. A native project with no local library table does not establish stock alias validity.
5. For `${KICAD*}`, SparkFun, user-variable, absolute, submodule or unknown library identifiers, record the exact original reference and evidence of revision/version from the original project metadata. Do not create alias mappings, substitute current libraries, fetch whole library repositories, follow website scripts or fabricate a historical identity. If the two SparkFun projects reproduce the already known unresolved historical alias pattern without authentic revision evidence, stop that closure branch and report it; do not repeat an unbounded library crawl. Additional fetching needs a separate bounded plan.
6. Compare design ancestry across the three projects and the prior 16-board population. Ideal Diode repeats four circuit channels; HSTX is a passive connector breakout sharing a vendor template; OLIMEX is related to iCE40-HX1K/HX8K extension-board circuitry. Product names, repository boundaries, board rotations or repeated channels are not independent families. Record provisional shared schematic/footprint/circuit lineage and defer an independence claim until structural comparison.
7. Produce a structured record per actual board with acquisition state, matched native files, source hashes, declared/exact redistribution basis, all unresolved references, native format/support blockers, family caveats, and next bounded action. Keep complete/eligible counts separate. Newly acquired or inspected designs are development-exposed; no reserved prospective holdout geometry is read. Take an after-inventory and require byte equality with the original acquired and preexisting inventories. Preserve reports in a new ignored audit directory; the lead curates only rights-cleared small metadata for public Git.

The current near-term preference is a manageable modern matched project if its authentic local/stock closure can be established. This is a priority for inspection, not a promise that either modern SparkFun project is eligible. OLIMEX's legacy project format remains a distinct farther support investigation. No routing comparison, quality metric, native acceptance or population success rate is produced by this audit.
