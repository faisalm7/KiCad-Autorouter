# Exposed stronger-incumbent cohort

This developer experiment reuses the matched IR caller and shared validators.
It compares stronger stock Freerouting B2 with the existing C pruning strategy
on Sonde, NUS USB LED, Push Button LED and DS18B20. Arc's named-class policy
remains two unsupported rows in the ten-row population. The table is a static
source catalogue; `prepare` creates the actual frozen experiment protocol.

Both methods have 120 wall/full CPU seconds. C pays for its own fresh stronger
incumbent and retains its 25-second finalization reserve. Both methods use the
same free-angle, disabled fanout/optimizer and engine-only 20um clearance
margin. Three positive-global-minimum sources require the private strict-width
v2 policy; DS18 uses the unchanged v1 policy and retains its zero-zone control.
Original native/task/engine widths, original rules and design constraints stay
unchanged. No public default or preset is promoted by this experiment.

Each eligible result pays its complete preparation, own arm, entire common
pure reader, timing rounding and the bounded 30-second report allowance, under
240 delivered wall/full CPU seconds. Historical control and original-source
qualification costs remain visible context; current replay is charged anew.
The completed report's actual enclosing exit and full timing must also pass
before any final result is qualified. A report cannot certify its own exit.

From the durable checkout, on the clean verified source commit:

```sh
.venv/bin/python -B experiments/stronger_incumbent_v1/cohort/command.py --source-head HEAD_SHA --stage prepare
```

Run the eight fixed `project--arm` stages sequentially, in table order, then
`read` and `report`, using the same source SHA. Wrap **every** command in
`/usr/bin/time -p`; preserve separate `STAGE-time.log` and `STAGE-command.log`
under `.runs/stronger-incumbent-cohort-timing-001/`. The stage names are
`sonde--B2_stronger`, `sonde--C_stronger`, `nus-usb-led--B2_stronger`,
`nus-usb-led--C_stronger`, `push-button-led--B2_stronger`,
`push-button-led--C_stronger`, `ds18b20--B2_stronger`, `ds18b20--C_stronger`.
Existing run IDs must never be overwritten. Missing prerequisites or changed
source/core/binary bytes refuse preparation. Cancellation returns 130.

The current owned strict-width control is replayed through current shared
checks. The older v1 control is explicitly historical Native evidence, with
its original captured rules and complete costs; it is not described as a
current whole-route replay. Original source gates preserve NUS's failed old
aggregate and typed field supplement. Genuine pre-policy LED/Arc originals
remain historical, unguarded jobs; DS18's actual guard events are replayed.
Fresh candidate acceptance always uses the current complete gates.

These exposed boards cannot establish untouched or independent-family
superiority. Keep failed methods, rejected candidates, warnings, costs and the
Arc refusal in the final report. Prior B0/B1/tuned-B2 results remain separate
recorded context. This is neither a new support claim nor a formal release.
