# Flat schematic class parity prerequisite

This is a bounded support investigation, not production routing support. The current product correctly refuses schematic class directives and hierarchies. Runtime006's retained owned counterexample exported `CRITICAL,POWER,Default` on ROUTE while the PCB resolved `POWER,Default`; native DRC and field parity alone did not catch the lost class intent. Exporter availability is already demonstrated and is not tested again as a discovery.

`compare.derive` joins every complete numbered terminal partition before requiring exact net labels and effective class identity. It checks source symbol/footprint identities, original PRO hashes, source/native layer records and all four explicit scalar parameter parents. Its initial identities are `Default` or an exact configured `NAME,Default`; arbitrary encoded strings are not split to infer constituents. Hierarchies, ambiguous names, additional dimensional/electrical intent, aliases, incomplete terminal censuses and unknown/composite inheritance refuse. This pure function cannot establish that any Native process ran. Its acceptance/routing/production flags are always false.

The small `retained006` packet is project-owned GPL source and actual historical Native output, copied byte for byte. Its manifest and the existing public counterexample pin the old route receipt; that receipt pins field/netlist evidence. Historical absolute paths are preserved as observation data. No research archive is needed to reproduce the comparison. This unsafe old routed control is not an accepted product candidate.

One new positive changes only the owned schematic flag from CRITICAL to the already configured POWER on the retained routed PCB. PCB, project dimensions, every existing route and all other source content stay fixed. This is a synchronized diagnostic input, not an automatic source repair or an independent board family. Every existing route is protected. The old negative is compared again with the pure code; its Native work is not repeated or charged as fresh execution.

The frozen study uses the existing bounded runner, shared exclusive Native lane, BoundJob, p.validate_candidate, immutable/companion checks, PRL protection, shared refill/final full-schematic readback, existing final-netclasses and field-netlist output, process checking and guarded publication. It runs no routing engine. A positive requires actual fresh original-rule refill/final Native0opens/0blocking/6warnings/2ignored checks, exact protected design, complete three-partition class agreement and specific ClassIdentityMismatch for the retained negative. Unknown parsing/binding errors do not qualify the negative. Missing outputs, changed inputs/tools, failed cleanup, truncation or late invalidation clear qualification.

Limits are120seconds total wall and parent-plus-waited-child CPU including preparation/replay/publication,20MiB aggregate output scratch,2GiB sampled process-group RSS and256KiB per-step logs. The existing inner BoundJob128MiB guard remains separate; these are polling limits, not OS quotas. Research, source authoring and independent AI review are separate unmeasured costs. No paid service, private CAD, API account or network is required during the study.
