# Experimental architecture and current limits

The current implementation is a Python modular command-line program with an isolated native worker and one Freerouting process. It is a reconstruction, not a new routing algorithm. The installed KiCad 10.0.0 and Java25.0.2 are pinned in `toolchain.lock.json`; no application was upgraded. Python3.11 runs the coordinator; only KiCad's bundled Python3.9 loads pcbnew.

The source project is hashed, copied, and never written. Whole-board tasks remove only unlocked tracks/vias/arcs in a copy; partial-completion mode treats all existing routes as protected. A bounded process supervisor executes DSN export, Freerouting2.5.0, and SES import. The SES importer can rewrite native metadata and format, so only its route objects are transferred into the original syntax tree, translating net codes through names. Every other original field remains present. Zone refill runs in a separate native copy; only derived filled polygons transfer back. Final DRC runs on a byte-identical separate copy with original rule/project files. The final emitted candidate hash, original file inventory, report inputs, versions, commands and resource receipts are bound together. Added rules, altered rules, source changes, missing protected copper, modified immutable fields or failed native checks reject the result.

This preserves original syntax semantics conservatively. It does not prove every possible KiCad constraint is supported. The preflight blocks custom rules, class mappings outside qualified policies, custom pads, net ties, advanced vias, DRC exclusions and disabled core checks. Qualified two-layer class paths audit native assignments and exact DSN/generated route dimensions. The guarded [parent-class scope](native-parent-classes.md) now has actual whole-board and protected partial CLI qualification on an owned diagnostic fixture; selected composite classes remain blocked. Class dimensions are routing targets, not inferred electrical requirements. Supported-format coverage is experimental: native versions 20241229 and 20260206, two/four copper layers; class transport remains two-layer only. User-supplied designs require engineering review. High-speed, RF, high-voltage, HDI, differential timing and physical/electrical correctness are unqualified.

[Selected-net routing](routing-preferences.md#selected-net-rerouting) is implemented narrowly for native completion-only mode with all source layers. Nonselected/unnamed and locked copper remains exact; failures on other nets still reject. Captured complete schematics participate in final native parity and effective-field checks. The harmless Datasheet absence bridge is limited to the qualified flat 20250114 context; hierarchy and real field mismatches remain unsupported or rejected. [Current requirements and evidence](../REQUIREMENTS.md) distinguish these limits from routing acceptance.

A routing-scope acceptance requires zero native opens, zero blocking findings, zero exclusions, no policy-critical findings at any severity, preserved invariants and budget compliance. Warnings remain visible and whole-project DRC cleanliness is separately reported. A failed or missing report is never a pass. No candidate is applied to a live KiCad editor; separate candidate projects are the only output. Save/close the original and open the candidate separately for human review. Disposable-copy loading and actual GUI DRC were exercised; see gui-workflow.md. GUI detection, unsaved edits, native undo and transactional apply/reject interaction have not been qualified.

## Baselines and experiments

B0 is the stock DSN representation and Freerouting2.5.0 with explicit bounded settings. B1 converts copper graphics into conservative DSN keepouts and suppresses exported plane declarations while retaining native zones. B2 uses the same adapter with tuned settings and a bounded three-cost portfolio. C obtains its own validated incumbent and charges native-validated redundant zone-net route deletion to the same total budget. Actual complete-schematic gains on three exposed circuits and all failed trials are recorded in [STATUS](../STATUS.md); they do not establish broad routing superiority or independent families. KRT alternatives were actually exercised and rejected for immutable changes and native copper violations; see krt-spike.md. Neither synthetic smoke success nor the historical adapter board establishes superiority.

Initial real results exposed an isolated-configuration crash and native `.kicad_prl` creation. Failed attempts are preserved. Three isolated KiCad directory variables give a working native configuration; the precise crash cause is not claimed. Native local-settings side effects now occur only in disposable validation copies.

## Resource and security limits

One sequential heavy worker; Freerouting sees one CPU and a2GiB Java heap. Parent and child CPU and native peak RSS are measured; RSS is not a sum across descendants. A hard task deadline is divided among every subprocess and includes Python/validation overhead. Logs are capped, process groups cancelled and ordinary descendants killed. Detached descendants or a supervisor SIGKILL are outside cleanup guarantees. Process-group RSS and per-run output size are polled against4GiB/512MiB guards; polling can overshoot. Total cache/data size and free disk are checked before runs. These are operational guards, not OS-enforced memory/filesystem quotas. Monitoring CPU is included in total CPU: macOS libproc executes in the parent, while other-platform monitor helpers are separately charged.

Freerouting's startup performs a version check even with analytics disabled. A tested macOS `sandbox-exec` profile denies network access for the entire engine process. This adds a process restriction and changes no global protection. The public release JAR is downloaded by pinned size/hash, not committed. No paid service, private-board upload, model inference or telemetry is required by the runtime.

## Learning decision (G6, current evidence)

No learning component is justified at this stage. Observed stock failures include deterministic interchange fidelity failures; the alternative engine also changes copper geometry. The current population has 25 canonical acquired boards, eight statically eligible and 17 unsupported, with no proven independent pedigrees or untouched holdout. Three complete-schematic pruning comparisons are exposed development evidence, not credible family-separated strategy-selection data. Deterministic deletion tests a concrete route-quality hypothesis without model inference. Revisit learning only after broader qualified coverage reveals complementary strategies and enough licensed episodes for family-disjoint evaluation. No weights, training accuracy, or model advantage is claimed.

## Bounded compound deletion hypothesis

The optional feedback policy extends the existing deletion strategy. A failed deletion may leave new native dangling-track warnings while preserving connectivity. Exact UUID references can propose additional eligible segments on that original zone net. All proposals reapply cumulative deletion to the unchanged accepted incumbent and receive full native checks; no report warning or failure is waived. Two follow-ups/eight extra routes are maximums within the same32trials and total budgets. Default single deletion remains available and is the direct ablation. A five-arm frozen development experiment compares both policies with B0/B1/B2. This is an engineering heuristic, with no novelty claim or presumed superiority.

Two earlier production multiclass attempts remain failure evidence: the first timed out before SES because intended inner timeouts were malformed; the repaired completion-only run emitted an SES but generated sub-target neckdowns and a new blocking thermal. The later owned parent-class CLI qualification does not change those outcomes. Changing imported widths after the fact would risk new collisions; settings/geometry mechanisms must be diagnosed and independently native-checked. Original targets, rules and zone thermal intent stay fixed.

KiCad10's official net-class documentation explicitly describes track width/via sizes as routing defaults, not minimum/maximum DRC constraints: https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#net-classes . The current exact-target generated-route gate is a deliberately conservative support policy, not evidence that a narrower above-floor route is electrically illegal. The interf002 width rejection must be distinguished from its actual blocking thermal violation. Any future policy change must preserve and audit native class resolution, exported targets and original hard rules, report deviations transparently, and receive separate native qualification; it must not be relabeled as fixing an original DRC width error.

Native pad-stack controls001–003 qualify one narrow severity-policy exception. The original `padstack: warning` setting is preserved, while a shared application predicate rejects actual critical warnings and `padstack_invalid` errors. Receipt verification, route improvement, separate-copy handoff and all measured candidate selectors use that predicate. Native error counts/severities remain literal; policy rejection reasons are separate. This is validation support, not a routing-strategy improvement. Multichannel is statically eligible, but later complete-schematic export rejects 115 additional warnings; historical board-only placement results do not qualify current complete-project acceptance. See [STATUS](../STATUS.md).


## Experimental thermal completion recovery

`recover` starts a fresh completion-only combined-adapter attempt. It holds 40 seconds from the total budget for a possible recovery and final emission, then uses the remaining wall/CPU allowance for the engine attempt. A separate 15-second reserve protects final validation. The whole operation charges parent and waited-child CPU, including metadata processes, native geometry acquisition, bounded graph search, failed repair trials, final refill/DRC and receipt checks. Exhaustion rejects the final result; reserves do not guarantee completion.

Only a sole unexcluded native thermal error can trigger recovery. The current mechanism observes the exact failed candidate, uses original netclass width, and searches at most four new straight bridges with certified saved-copper paths to distinct same-net terminal annuli. It supports two copper layers, a round PTH target, round physical holes, one zone layer and bounded populations. Exact path tests avoid all physical holes and contour boundaries; they do not establish ampacity or a globally qualified copper-component model. Full native validation checks new copper under unchanged original rules. The target-zone fill must remain exactly unchanged, and final emitted candidate bytes must match the validated selection. Otherwise the old geometric witness cannot authorize delivery.

The geometric/native positive and exact bridge-removal negative have executed on one exposed development candidate. Fresh end-to-end thermal-paired-001 at cbae125 accepts C under fully charged 120-second caps while B2 retains a thermal error. This qualifies one narrow exposed-input outcome, with different predeclared allocation policies; independent full-budget completion-only and stock/standard-adapter ablations remain necessary to isolate repair from allocation. B2 comparison uses its own tuned three-cost portfolio; C gets no free baseline candidate or reference route. Floor-export correction is a separate adapter investigation and is not part of this mechanism.

## Experimental single-body thermal contact

A separate opt-in prototype proposes at most four short, pad-aligned tracks near a sole native thermal error. It uses the exact reported copper layer and fresh native pad geometry, including narrow ordinary SMD support. These are speculative proposals: endpoint membership in saved copper does not certify a path, current capacity or safety. The original certified two-body repair remains the default.

The fresh NUS diagnostic pays for its own connectivity classifier and route, preserves a rejected selected child, and validates any added skipped-net copper against the whole original project. Saved refill, fresh full-schematic checks, original constraints and warnings, final metrics, removal-negative control and complete wall/CPU caps remain mandatory. [Source, frozen protocol and unexecuted Native gate](../evidence/native-contact-source-001.json). No normal CLI option or new support/quality claim follows from software tests.
