# Experimental placement-backed pruning

This experimental implementation extends the native-validated zone-net deletion strategy to the existing placement/floor input policy. It is deterministic local code, requiring Python3.11, pinned KiCad10.0.0 and Freerouting2.5.0; no AI subscription, model or route-time network is required.

Ordinary schema4 routing keeps the original SES/import/refill reconstruction and eight native/engine stages. Named standard/tuned/completion-only search and default/low/high via costs are separate from the fixed20µm geometry margin. All three width-reduction prohibitions stay enabled, and final acceptance uses original project files/rules.

Schema5 C obtains its own fresh tuned/default incumbent. Only generated unlocked routes on original copper-zone nets select deletions. Whole-net then longest-route proposals, bounded native dangling-warning feedback and every failed attempt are retained and charged. Selection requires native acceptance, no worse length/vias, a strict Pareto improvement and no added warning identities or multiplicity. Final delivery repeats native refill, dimensions/connectivity/DRC and metrics. Readback reconstructs parent→declared eligible deletion→saved refill→candidate, verifies the ordinary incumbent receipt and binds every failed worker to the full compute history. Mutable local receipts are consistency evidence, not authentication or physical certification.

The experimental branch deliberately retains its narrow whole-board scope; existing production settings/protected-copper controls continue through their separately qualified paths. This experiment has not yet extended production support, selected nets or live editor application.

First run the promoted engineered controls with the shared bounded outer runner. Positive deletion must preserve legality and reduce redundant copper; necessary deletion must yield an actual targeted open. These owned fixtures cannot establish unrelated-board quality improvement.

Reproduce a new run using the existing sequential comparison helper and a fresh directory:

```sh
.venv/bin/python -B scripts/experiment_paired.py --project sonde --system native-all --output .runs/sonde-comparison-NEW
```

Run only when a fresh experiment is warranted, with a prospective protocol and full budget accounting. Completed candidate/report hashes, failures and final validation stay unchanged. New board support must pass original-design qualification before a routing-quality comparison.

Native-only pruning now has an experimental explicit incumbent scoring API (`autorouter.strategy.prune(..., incumbent_scoring="via_high")`). It performs and charges its own fresh solve; it cannot reuse a B2 candidate. A persistent run contract, actual engine settings/full argv/cwd, native receipt hash and phased worker history bind the choice. Normal CLI customization continues to use the existing explicit saved preferences and original constraints. No fresh High-incumbent quality result is claimed until its frozen experiment and every final native/original check run. Analog's earlier default-C result is a tradeoff against zero-via High and remains unchanged. This alternative is exposed development tuning; all method-selection/exploration costs and failures remain separate from per-method runtime caps.
