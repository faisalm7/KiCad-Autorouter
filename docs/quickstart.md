# Saved-project workflow

Start from your installed launcher and your own complete saved KiCad project. [Start here](../START_HERE.md) covers launching and source selection; [advanced installation and CLI](install-existing.md) covers terminal setup. The workflow does not require an AI account, model endpoint, research archive or prepared GUI session.

Use the portable example or your own supported complete project with fresh inspection. The installed ordinary workflow completed the example with zero opens, zero blocking findings and one inherited warning. An earlier build completed the same task from a live copilot proposal. Each result covers its stated Mac and task. Open **Conversation** to enter an explicit local placement request or use
the optional hosted assistant. **Preview placement** checks commands such
as `Select J1` and `Routing time 75 s` locally. **Review data and send…**
displays the data and cost for an optional model turn. In either case, review
and edit the proposed settings beside the board before choosing **Use settings**.
Placement, routing and final checks still need the ordinary approvals below.
[Current Conversation controls](saved-project-workspace.md).

1. **Open the saved source.** Double-click **Copperpath.app** in Finder and choose the saved project. Inspection starts automatically. Keep the PCB, project, complete schematic and original rule files together. If the source is open, save and close its editors and use **File → Close Project** in KiCad manager. Then choose **Refresh inspection**. KiCad counts open connections after refill.
2. **Choose routing or placement.** For direct routing, choose scope, protected content, layers and budget in ordinary controls. **Finish gaps** preserves existing routing; rerouting unlocked copper must be explicit. For placement, select eligible movable parts and an allowed rectangle. All unselected/fixed parts stay fixed. Orientation and side remain unchanged. Keep existing copper protected, or explicitly permit the supported affected-net rebuild policy and review exactly what it will rebuild and retain.
3. **Compare placement drafts when requested.** Use **Find alternatives** and inspect the diagram, numeric coordinates and copper plan. The placement constraints also apply to coordinate edits. An invalid edit retains the previous pose. Builds with **Approve placement and validate** can show a direct start inside an explicitly set area for a supported pair. The policy is visible in the plan and adjustable under **Advanced settings**. Source collisions require correction in the design. The search may return no changed alternative. Review and approve the exact draft before continuing to routing. Earlier builds use a draft acknowledgement followed by **Validate placement**. [Current workspace](saved-project-workspace.md).
4. **Preview and route.** Preview checks scope and, for **Finish gaps**, the missing connections KiCad finds. **Start routing** works on a copy and runs its own validation. Keep the saved source closed and unchanged. **Cancel** requests cleanup and revokes results. Wait for it to finish. A source, settings, pose or policy change requires a fresh preview or placement review.
5. **Review the result.** Choose **Review result**, then compare **Copper changes** and **Findings** in the same workspace. The layer switch keeps new and protected copper distinct. Use the optional **Detailed report** for full KiCad plots including zone fill. After reviewing the findings and closing any KiCad review project, check the review acknowledgement and choose **Accept result** or **Reject**. Use a fresh export after accepting.
6. **Make a fresh separate export.** Fresh export reruns original-rule Native validation, including refill/connectivity and schematic/design/protected-copper checks. Open only through **Open checked export** while the retained proof is current. Normal KiCad opening or subsequent editing can change the project/file set and make that proof stale. Save further edits as a separate complete working project and choose it as a new source task; never renew proof by editing receipts or restoring sidecars.

Native routing acceptance is scoped to the requested routing task and bound candidate. It is not the same as a completely DRC-clean project, and neither establishes electrical or manufacturing suitability. Review every warning and ignored check; preserve the original rules and protected content.

The 101 GUI124 control observes active owned Native source-DRC cancellation and cleanup. Genuine changed-warning interaction, exact queued-opening timing and every Native cancellation phase remain unexercised. No complete GUI CPU/interaction performance or human cleanup benefit is measured. One owned example qualified for a checked live move and native Undo.
