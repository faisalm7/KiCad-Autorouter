Four concrete parser/constraint-consistency defects were reproduced and their narrow fixes checked. This reviewer ran no native KiCad, solver, JVM, subprocess, network or Git commands and edited no tracked source. The retained settings probe is a prior actual JAR parser/merger observation; it explicitly never loaded a DSN or created a routing job. This review does not qualify the subsequent native positive, any routing gain or a release.

## Findings and resolution

1. **Normalized quote sentinel emitted.** The first partition used `adapter._parse_dsn` but emitted `sexpr.dump`. The exact retained actual task input and prior `partitioned.dsn` produced the internal quote sentinel in the engine DSN. The existing DSN parser rejected the emitted bytes as containing its reserved sentinel. The lead changed emission to the existing `adapter._dump_dsn` and added a parsed roundtrip check. The actual retained input now reparses; parser, units, structure, placement, library, wiring and full net/pin rows stay exact.

2. **Interclass references became dangling.** A synthetically amended two-class DSN with `class_class` pointing at Power was admitted even though an entirely nonselected Power class was renamed into an ignored clone. The preserved reference no longer resolved. Cached pinned Network.java resolves both class names and warns/skips missing classes; keeping reference bytes did not establish unchanged rule meaning. The lead now rejects network scopes outside net/class and per-net scopes outside pins. The same retained interclass input now rejects. This is a pure counterexample; it does not prove that the current KiCad exporter emits interclass references.

3. **Default aliases could merge chosen class rules.** Two classes named kicad_default and default, with distinct chosen-net widths, passed the original casefold-only collision guard. Cached pinned KiCadNetClassNames treats both as the same Default engine identity, and Network.insertNetClass writes each rule payload into that shared class. A literal secondary class named default was permitted by the existing project qualifier. The lead now canonicalizes those engine aliases before rejecting duplicate identities. The exact retained alias input rejects. No fresh JAR execution was needed or claimed.

4. **Adapted scope input could weaken unchanged native class rules.** In a complete synthetic Default/both-adapter receipt, the controlling full `check_result` passed. Changing only the scope-input class width200 to100, recomputing its partition/output binding and task hash, and updating the adapter's reported output hash still passed. The original native.dsn and its original hash remained width200. Readback compared only that reported adapter output hash. The existing adapter promises an unchanged complete network AST, including class rules. The lead added an independent parsed native-network versus prepartition-network comparison. The same stored positive remains current and the same width mutation now rejects. The candidate, original project, captured choice and fabricated final native input/report were unchanged. This demonstrates a consistency gap, not native acceptance of an invalid route.
