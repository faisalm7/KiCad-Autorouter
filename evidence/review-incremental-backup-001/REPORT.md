# Incremental backup independent review

The corrected implementation has no remaining blocker within this source and small-fixture review. This is not a full project backup/restoration or independent disk-failure protection. ROOT must checkpoint the corrected source and perform the real chain restoration before claiming that milestone.

The initial frozen source (`bbf34dbc…`, author manifest `440b803f…`) had two reproduced defects. Both original failures and unchanged positive controls remain in `reproduction-001.json` and its log:

- **R1, extraction path guard:** after a valid tar passed its first audit, replacing it with a `../unexpected-outside-restore` member caused the second pass to create a file outside the new restore tree, then raise `KeyError`. This was entirely within a tiny reviewer-owned fixture. The original source payload remained unchanged.
- **R2, cancelled canonical proof:** an owned Python child sent itself SIGTERM immediately after the proof write and exited −15 while leaving `verified=true` at the canonical path. SIGINT already invalidated correctly; the unchanged positive also passed.

Corrected source `5489148a49c577ee60bff6ea3b042b13f2ce1e674bf0bddb1d8047cb228383a6` passes the same five cases. The archive replacement is rejected before the outside file exists; both actual signals now leave only an invalidated proof. Only the reproducer output directory was changed for the second run, preserving every original artifact. The code diff changes three existing functions (`audit_archive`, `restore_archive`, `publish_check`), adds shared per-member/payload checks, and imports `signal`. It checks exact members, regular/directory types, sizes, duplicates and complete membership in both archive passes before opening destinations; payload reads are bounded by the declared size plus one sentinel byte. SIGTERM handling is scoped to proof publication and restores its previous handler. This improves the shared schema1 extraction path too.

Four final focused methods passed in 1.135 seconds: two deltas with exact final byte inventory and Git refs; empty delta plus legacy schema1 full restoration; seven changed-header cases; and bounded/truncated/overflow payload reads. Four pre-fix functional methods also passed, including omitted deletion/payload accounting and rehashed bad delta payload rejection. These used small actual Git repositories and archives, not a production backup. Existing test source containing the synthetic credential header was imported from its original location; it was not copied into this review.

The full implementation independently recomputes changed/new rows and explicit deletions from parent and target inventories. Deletions and replacements affect only a newly created restore tree. File↔directory transitions, absent scopes and empty directories are covered. Each latest Git bundle remains standalone; parent receipts and successful full-base restoration evidence are hash-bound. Missing/changed parents, ancestry cycles, escaping references, hardlinks, symlinks, malformed JSON, conflicting members and count/size ceilings reject. Complete final inventory equality is required after each applied delta and at successful restoration publication. New incremental checkpoints explicitly report `full_restoration_tested=false`; the CLI `--verify` reconstructs the complete chain and tests the restored CLI. Older schema1 receipts do not need the new schema2 metadata.

Limits remain 2 GiB per target snapshot/archive/bundle and 100,000 files, plus a directory-count bound. New limits are 16 receipts, 32 MiB per receipt and 128 MiB combined chain metadata. Secret/path guards remain in the initial source inventory; their narrow known synthetic-test exceptions are unchanged. No credential-like content, unrelated file, user/global configuration, native tool or network resource was accessed by these controls.

Finite file checks and mutable hashes are consistency evidence, not cryptographic authentication or atomic protection from arbitrary simultaneous writes. SIGKILL/OS crash is not handled by the publication exception path. Private scratch restores and partial/invalidated artifacts remain retained; prior backup archives and source evidence are not overwritten. README accurately distinguishes incremental integrity checking from a full restore and warns that local backups do not protect against failure of this Mac's disk.
