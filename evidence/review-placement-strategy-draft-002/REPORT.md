## Findings

1. **P1: incomplete trial could authorize native-warning feedback. Reproduced, then targeted fix observed.** `check_pruning_result` originally allowed `completed=False`, `accepted=False`, `status=quality_rejected` as a feedback parent; it skipped that parent's native candidate check and used its arbitrary `native` and candidate fields to derive the next proposal. `feedback-parent-001.json` records a passing lineage check with zero trigger workers. The lead added strict incomplete state/error checks, completed-parent requirements and computed completed-row status. `feedback-parent-003.json` against `placement_strategy-after.py` now rejects both invalid feedback parents while admitting a legitimate failed attempt with no feedback. Intermediate `002` is retained: its no-feedback fixture incorrectly kept `quality_rejected` status and correctly rejected after the fix. Final candidate legality was never shown to be bypassed; the defect concerns the claimed native feedback evidence.

2. **P1: new placement C cannot be admitted by the existing paired summary. Reproduced, lead notified; integration fix pending this review.** `experiment_paired` dispatches placement C through `q.summarize` with `operation=prune`. `experiment_quality.summarize` still requires legacy `incumbent_baseline` and `incumbent.receipt` fields, while schema 5 emits `incumbent_receipt_sha256` and `incumbent_assigned_seconds`. `summary-contract-001.json` observes `accepted_in_receipt=True`, `receipt_verified=True`, `within_equal_budgets=True`, but `protocol_contract_verified=False` and `accepted=False`. This will misclassify actual valid placement C output. Use explicit policy-aware incumbent/contract verification before comparison and retain the regression.

3. **P2: replay checks proposal membership, rather than the complete deterministic schedule. Reproduced and open.** The implementation schedules whole-zone proposals, then longest-first individual routes, each base proposal once unless removed. The checker accepts individual-before-whole and duplicated base attempts (`proposal-order-001.json`). Each proposal still has to be an eligible deletion and each admitted candidate remains native-validated, so this does not weaken original design preservation. It limits claims that receipt readback proves the exact declared search schedule. Either replay the deterministic policy, or document this narrower consistency guarantee. Budget and population checks must remain unchanged.
