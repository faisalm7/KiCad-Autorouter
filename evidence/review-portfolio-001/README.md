# Adversarial review of prospective B2 portfolio draft

Read-only review of `.runs/baseline-strength-review-001/prototype/scripts/experiment_portfolio.py` and its `pipeline.patch`, with one new lightweight mocked-stage executable control. No native/engine job or tracked edit was performed.

`python3 -B .runs/review-portfolio-001/reproduce.py` reproduced a fail-closed defect in the initial draft: final accounting, eligible summary publication and post-write cap checking were outside the cancellation handler. Injecting a KeyboardInterrupt after the eligible summary's atomic save let the call escape with `status=completed` and `comparison_eligible=true` still on disk. The control simultaneously moved measured CPU above120 to demonstrate the skipped reconciliation. The original stored total was75. This is an injected control-flow test, not native routing evidence. `reproduction.json` records the initial observation. The implementation agent and lead were notified before promotion.

Read-only findings otherwise support the planned design: the complete invocation uses RUSAGE_SELF+RUSAGE_CHILDREN deltas, includes preparation and selection, and does not sum nested child receipts into those totals. Each next attempt gets the lesser remaining wall/CPU allowance minus15 seconds, and attempts are withheld if current engine/native reserves cannot fit. All accepted eligible trials are rechecked before final ranking, plus the chosen trial again. The fixed via-cost settings are checked against actual retained engine argv/process receipt and frozen profile declarations. Native metrics are validated before ranking. Selection preserves the candidate and its original exact native receipt; the portfolio summary separately charges all attempts. Receipt/native/source/code checks remain active.

The fixed via-first, then length, then index ranking is consistent with the pruning strategy's quality order, while the retained Pareto frontier prevents pretending a fewer-via/longer-route tradeoff is universal dominance. This is a stronger predeclared baseline hypothesis, not a guarantee of optimum tuning. The actual engine settings reflection probe was performed by another agent and is retained separately; this reviewer has not rerun it or routed a board.

Suggested evidence improvements, separate from the cancellation blocker: capture portfolio/attempt host load averages, pair invocation UTC begin/end with monotonic durations, and aggregate child/group RSS from retained process steps. No generalized success or native qualification follows from mocked controls or this review.
