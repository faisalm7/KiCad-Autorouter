# Selective custom-area observation draft

This adds one Java observer and one finite comparison helper to the existing mixed-transport experiment. It does not add a runner, acceptance framework, routing, SES writing or production support.

`SelectiveAreaProbe <captured-mixed.dsn> <fresh-observations.json>` performs exactly one false-global manager import and awaits post-load processing. It uses package-default `MixedClassProbe.observe`, `routeGeometry`, `applyLocal250`, `settings`, `boundedError` and `AreaContactProbe` serialization/hash helpers; those tracked sources are unchanged. The observer captures the pre-local state/routes, applies the existing two-pad local250 operation, captures the pre-selective state/routes and predicates, then enables only the two audited USER_FIXED areas. It explicitly sets `ignoreConduction=false`, refreshes all tree entries, and captures the post-selective state/routes/predicates. The original SYSTEM_FIXED GND area's false flag is preserved. The global flag change is not described as unchanged original state.

All three areas are inspected against every ordinary trace/via. Every item has a recorded tree-entry check. Every trace has bounded tile queries through `checkTraceShape`, raw overlap IDs and separately flag-filtered overlap IDs. Generic `checkShape` and foreign-Pin `isObstacle` are deliberately not used as the positive trace-obstacle test. Raw GND overlaps may remain; filtering is the relevant observation. No universally clear query or reduction in whole-board errors is presumed.

Input is bounded to 1 MiB and JSON output to 16 MiB, with fresh exclusive creation. Census/shape loops reuse the existing 4,096-item bound, plus exactly three areas, at most 2,560 routes and 16,384 queried trace shapes. The caller still supplies the existing shared 180-second wall/full-CPU cap, 64-MiB aggregate bound, pinned isolated JVM/network denial, process cleanup and publication guards. This standalone helper does not replace those controls. Partial observations and the first mutation/capture exception are retained; later state/geometry/predicate/settings capture errors have separate bounded fields. A failed case exits 2 after writing its failed observation. JVM errors outside `Exception`, interruption before output, or serialization/output failure remain process failures for the existing caller to retain, not successful observations.

`compare.compare(observed, expected, verified_local_observation)` re-runs existing `transport.validate_local` over the **actual retained false/true local250 pair**, then requires the new single false pre-local/local states, audit, settings and DSN digest to match that actual false baseline exactly. It never fabricates a second new import case. The caller must capture and hash-bind that prior evidence and its original-source/derived-DSN basis using the existing controller; the comparator does not authenticate mutable JSON. At integration, either retain this dependency or factor the existing single-case validator explicitly; do not drop baseline qualification or pass a claimed boolean.

The helper delegates all route-coordinate witnesses to `ses_checks.geometry_check`. Reversing only the two area flags, corresponding derived foreign trace predicates and global ignore flag must recover the complete pre-selective state. Routes, nets, widths, matrices, geometry, identities, contacts, fixed states, plane-net flags and fill flags must remain exact. It checks the complete predicate/entry/query populations and rejects unexpected original-plane activation. This proves only an imported representation transition. Original native sub-micrometre route survival, original-board connectivity, solver lifecycle and native acceptance remain unqualified; prior SES exact-survival failures remain failures.
