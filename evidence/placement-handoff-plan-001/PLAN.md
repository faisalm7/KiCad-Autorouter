# Placement disposable review-copy: smallest qualified extension

Design audit only. Production behavior remains unchanged: `review-copy` blocks every non-native guidance policy. No implementation, native process, GUI action, network access or source change was performed. This is an AI review, not human PCB approval.

## Scope and reuse

First admit only an accepted **schema3 `placement-clearance-v1` receipt**, alongside the existing native-policy path. Keep `board-floors-v1`, unknown policies, diagnostic receipts and rejected candidates blocked until separately qualified. The placement branch already composes the floor correction; admitting it does not require silently admitting every schema2 floor receipt. Do not expose an override flag or reinterpret a schema3 receipt as native.

Reuse `pipeline.check_result` and its strict policy dispatch, raw native report, source/rules, complete evidence, DSN derivation and final candidate checks. Reuse bounded `placement_clearance.read_bytes/inventory`, strict `floor_route.read_json/canonical`, and the existing `handoff.review_copy` entry point. Do not add a second route/validator framework. No engine or native tool should run in ordinary `review-copy`; it prepares an explicitly unvalidated-for-further-edits disposable complete project for later manual inspection.

The command and destination layout can stay unchanged: a fresh external destination containing `project/` and `review.json`. It must never overwrite source, accepted evidence, an existing destination, a symlink path or a live editor. Do not open PCB Editor automatically. No live apply, reject transaction, undo, stale-editor detection, library installation or global preference changes belong in this extension.

## Exact boundary and concrete gaps to close

Current handoff captures the original receipt digest, calls `check_result`, rejects non-native policy, copies the complete candidate tree outside source/run, compares source/copy trees, then calls `check_result` again and binds both returned candidate identities plus the copied board hash. Six filesystem tests cover copying, collisions, protected directories, symlink ancestors, stale second checking and a changed-but-valid receipt switch. `test_placement_policy` separately proves schema3 remains blocked.

Two source-visible gaps matter before widening this boundary; these are design findings, not newly executed counterexamples. First, only the **board** in the destination is rechecked after the second checker call. A changed copied `.kicad_pro`, rule or library file during that call can escape the earlier full-tree comparison. Second, `review.json` is published without subsequent freshness/readback or cancellation invalidation, so a late mutation/interruption can leave a ready record. The proposed controls below must reproduce these before fixing. Do not remove the non-native guard alone.

Use a bounded strict receipt read before the first central check and retain its digest. Derive policy only from the central check; cross-check the strict original receipt and both returned policy/candidate identities. The only allowed new case is schema3 placement with its exact returned policy. All current central rules remain authoritative, including stale source, rules, protected routes, native findings, policy downgrade, copied code/lock and raw/report/process hash chains.

Before creating the destination, capture the complete candidate project with the existing placement bounds:32MiB,2000files,4000entries, regular files only, no symlink ancestors. Prefer `inventory(contents=True)` plus writing those captured bytes into a fresh destination, then exact hash verification; this avoids an unbounded `copytree` if a source grows after initial inspection. This is a bounded32MiB payload, not a new archive subsystem. Preserve all project/rules/library files; do not copy only the PCB or normalize project settings. Keep the destination outside both the original source directory and the entire evidence run. Leave a failed disposable directory for inspection; do not delete unrelated files.

Immediately before **and after** ready publication, require: original receipt digest unchanged; central `check_result` success with identical policy/path/candidate hash; candidate's complete project inventory equal to its captured inventory; destination's complete project inventory exactly equal to that same inventory; copied board hash equal to the verified candidate; strict canonical review JSON equal to the expected record. The schema3 central checker rechecks original source/snapshot/full evidence and bound policy after its own work. After any subprocess-bearing freshness check, repeat the material checks, including the complete destination project and canonical receipt, rather than adopting a new inventory. No check should rebase an earlier known-good hash set.

Give the copy/publication operation a fixed30-second wall and measured parent-plus-waited-child CPU acceptance ceiling; budget checks bracket bounded reads/copies and final publication. There is no native job and no hard CPU kernel quota. Explicit failure on oversized/slow evidence is preferable to weakening the ceiling. Scoped SIGINT/SIGTERM handling must restore previous handlers. Interruption, exception, stale input or final cap failure archives any ready canonical/partial metadata before best-effort rejected/cancelled publication; failed correction must leave no canonical ready record. Keep accounting labelled at its actual sample point and run a final postpublication cap check. Pure guards cannot promise atomicity against an adversarial concurrent process or abrupt OS/power failure.

The handoff record should add `input_policy`, source receipt schema/hash, original verified candidate hash, complete initial copied-project hashes and `native_validation_performed:false`. Its status means only `ready_for_manual_review`; no `accepted:true`, applied or fresh-DRC claim. Original native findings/warnings are available through the bound receipt, not rewritten into a new acceptance. Any subsequent GUI save, refill or project normalization produces a separate design state requiring fresh validation.

## Minimal qualification sequence

1. **Pure/filesystem controls.** Preserve the existing six controls and native default behavior. Replace only the schema3 refusal expectation after the positive branch is intentionally implemented; retain schema2/unknown/diagnostic refusal controls. Add actual-file tampering of the copied project/rules during the second checker, receipt/policy/candidate switch, source/rules/whole evidence changes, late canonical mutation and SIGINT/SIGTERM during final publication, failed corrective write, path collisions/symlink ancestors, output-under-source/run, nonfinite JSON and size/count growth before reads. Require no ready canonical record on every failure. Mocked validation in these tests establishes lifecycle behavior only.
2. **Copied actual receipt.** Use the owned placement production fixture's accepted schema3 receipt, first proving current positive readback and unchanged originals. Create one new complete handoff copy and compare every byte to the verified candidate. Retain semantic negative controls after a valid copied-evidence positive, including stale original/source rules, changed copied rules, policy downgrade and changed native evidence. Reuse existing actual receipt-control methods; do not mutate the original accepted run or claim relocated JSON is authenticated.
3. **Fresh native copied-project control, root sole lane.** On another complete disposable copy of the new handoff project, run pinned original-rule native DRC with in-memory refill, without saving source/candidate. Preserve report, process argv, project hashes and settings/ignored checks. Positive should reproduce the owned fixture's clean report and geometry. One independent copied invalid geometry (for example removing the required via) must produce the expected opens and remain invalid; do not make the handoff validator apply edits. Existing five native placement controls provide related algorithm evidence but do not substitute for checking this exact copy boundary.
4. **Actual PCB Editor observation.** Start with the owned fixture, then one disposable copy of the accepted full multichannel placement candidate because the fixture has no ordinary copper zone. Verify the path opened is the disposable board, record visible KiCad version and actual geometry/connectivity counters, run GUI DRC with zone refill, all severities and exclusions visible, export raw JSON and compare findings/ignored settings against the source-bound CLI report. Record any library/configuration differences; do not change preferences to suppress them. Full multichannel's96warnings remain visible and are not a clean-board claim. Protect originals and accepted evidence with pre/post inventories. Close/discard only the disposable project, record whether its board/project/settings/history changed, and confirm original/run invariants. Opening and clicking must be actual UI observations, not mocked claims. The earlier sonde GUI trial is background evidence only: it showed configuration-dependent warnings and `.kicad_pro` changes even after Discard.

Each native/GUI control is a separate bounded root-approved diagnostic with immutable inputs and its own outputs; no background watcher or new application plugin is needed. A tool-assisted GUI inspection is still AI inspection, not human PCB review or electrical/manufacturing approval. If GUI behavior, source dependencies or active windows cannot be confidently bound, retain separate-copy filesystem/native evidence and label GUI qualification incomplete.

## Files and stopping gate

Likely production edits after review: `autorouter/handoff.py`; a small scoped signal handler at `autorouter/__main__.py` only if the handoff wrapper cannot own it; `tests/test_handoff.py` and the explicit placement refusal test; `docs/gui-workflow.md`, placement guidance/README support wording only after actual qualification. No `pipeline`, floor, placement transform, source board, DRC severity or engine change is required. Native/GUI controllers can reuse existing isolated Job/runner and whole-project copy patterns rather than introduce another framework.

Before execution, audit/commit/push/read back the reviewed code and keep existing accepted native/floor/thermal receipt readbacks compatible. After actual copy/native/GUI observations, publish only owned/licensed selected evidence, preserve full raw artifacts and test backup restoration. If any gate fails, preserve the blocked policy or label the narrower achieved gate; do not infer live application support from a ready disposable copy.
