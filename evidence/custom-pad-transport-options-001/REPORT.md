# Custom-pad transport: bounded source investigation

**The smallest promising hypothesis is the unchanged logical pin and native rectangular anchor plus an exact same-net wiring polygon, with foreign-net obstacle behavior explicitly activated and observed. It is not qualified by the current evidence.** A concave padstack polygon alone is predicted to be convexified by the pinned importer. Replacing the pin's padstack shape with its original contained anchor and representing the remaining/full exact copper as an area may avoid that conversion without editing the original KiCad pad. All original KiCad candidates would still retain their exact custom-pad primitive, anchor, terminal identity and net.

This work read cached primary material, then fetched exactly five files (171,716 bytes) from Freerouting commit `b647a2f824cfbc54bc4dcaee71b03b7cd945eb76`, the previously checked 2.5.0 release commit. No Java/Javac, engine, native tool, GUI, dataset script or solver ran. The new source is not a byte-for-byte proof of each compiled JAR class. The saved prior JAR bytecode inspection is separately bound to JAR SHA `f6f51bb02245e8e717f9359bd260cc9c5c0b1bc0acc8b7cb2cd5b8ffeb5de3c7`. The root's actual padstack importer probe remains a separate execution gate; this investigation does not assume it passed.

## What the sources establish

1. **Padstack loss is downstream of the DSN syntax.** The saved pinned `Library` bytecode uses one `ConvexShape` per layer, applies `PolygonShape.convexHull()`, then stores one convex tile. Repeated shapes on the same layer write the same array slot; they are not a union. Saved `Polygon.transformToBoard()` itself constructs a polygon after coordinate conversion/rounding; the padstack-specific hull is a separate later step. Thus merely replacing KiCad's hull coordinates with a concave polygon or supplying several same-layer padstack shapes is not an adequate proposed repair. Actual importer observations are still required.

2. **A wiring polygon takes a different import path.** [`Wiring.java:357–486`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/io/specctra/parser/Wiring.java#L357-L486) recognizes polygon/rectangle/circle bodies, net, clearance class and fixed type; it transforms the body as an area and inserts `ConductionArea`, without the padstack conversion. Critically the call passes `isObstacle=false`. `(type protect)` selects fixed-state behavior; it does **not** make the area an obstacle. Missing net or unknown class may fall back, so import must prove one exact net and the intended class rather than rely on successful parsing.

3. **Concavity can survive the area conversion, but exactness remains an observation obligation.** [`Shape.java:518–554`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/io/specctra/parser/Shape.java#L518-L554) returns the transformed boundary directly when there are no holes. The narrow proposed scope is the already observed simple, five-vertex, filled, zero-width primitive plus contained 0.3×0.3 mm rectangular anchor: no holes, arcs, offsets, disconnected bodies or multiple primitives. Coordinate conversion rounds to engine integer points, so source-to-engine equality must be measured at the actual resolution; arbitrary sub-grid coordinates remain unsupported. The anchor may touch the concave boundary at its left midpoint; a strict-interior requirement for the whole anchor would wrongly exclude this source. Its center must actually contact the area.

4. **Connectivity and foreign clearance are independent.** [`ConductionArea.java:340–414`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/board/model/items/ConductionArea.java#L340-L414) derives same-net/same-layer contacts through trace endpoint containment or a drill-item center inside a tile, and provides area connection targets. Its obstacle and drillability predicates explicitly permit foreign routing when its obstacle flag is false. Those contact rules are not proof of symmetric graph traversal or a full route-width capsule. A pretty rendered fill is also not an acceptance witness. Native connectivity and clearance on immutable custom pads remain authoritative.

5. **There is an existing obstacle setting to investigate, not yet a verified command.** Cached [`RouterSettings.java:51–58,764–780`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/settings/RouterSettings.java#L51-L58) exposes `plane_as_obstacle`, default false. Cached [`RoutingBoard.java:1265–1290`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/board/facade/RoutingBoard.java#L1265-L1290) can enable obstacle flags on signal-layer conduction areas, update the global ignore setting and reinsert search-tree items. This bounded source set does not establish that the pinned CLI applies that field at the necessary lifecycle point. A future observer must read the effective area flag, board rule, clearance matrix and search-tree behavior after import/settings application. No silent global preference change is authorized.

6. **A structure plane is a poor transport choice here.** [`Structure.java:1070–1118`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/io/specctra/parser/Structure.java#L1070-L1118) also inserts a non-obstacle area. The current both-adapter suppresses every structure-plane declaration, so such copper would disappear. Cached `AutorouteConnectionRouter` and `BatchAutorouter` may treat connection to a conduction area as sufficient when a net is marked as a plane net. This could create false completion across separate pad bodies. Do not declare a custom-pad net as a power plane, change layer signal status, or bypass all-terminal obligations to exploit it. A wiring polygon survives the existing plane-suppression AST operation, but the current production floor auditor explicitly requires empty wiring and custom pads remain blocked. No gate is to be bypassed on the basis of these observations.

## Options and their present disposition

| Option | Present disposition |
|---|---|
| Exact convex primitive as one ordinary padstack | Plausible separate convex-only adapter scope; cannot solve the concave role. Requires actual importer and native transport checks. |
| Concave padstack or multiple shapes on its layer | Source/bytecode predicts hull or overwrite; retain as negative importer observations, not product support. |
| Original anchor pin plus exact fixed wiring area | Preferred small capability probe. Preserve one pin/net identity, exact body, effective foreign obstacle and no plane-net shortcut. Setting activation and reciprocal contact graph remain unverified. |
| Concave body as structure plane | Reject this proposal: conflicts with current plane suppression and risks plane completion semantics. |
| Convex hull plus a notch keepout | Does not restore terminal copper/contact semantics; can obstruct legitimate free notch routing. Not an exact representation. |
| Decompose into new virtual pins | Changes engine terminal census/mapping and may manufacture logical connectivity. Not within the unchanged-anchor proposal. Requires separate identity/union proof, not an immediate fallback. |
| Minimal engine bridge/fork | If the stock lifecycle cannot activate exact area's obstacle semantics, a narrowly audited importer-side area insertion with `isObstacle=true` could be researched. [`BasicBoard.java:560–598`](https://github.com/freerouting/freerouting/blob/b647a2f824cfbc54bc4dcaee71b03b7cd945eb76/src/main/java/app/freerouting/board/facade/BasicBoard.java#L560-L598) already exposes this representation. That is an engine integration change with new artifact/build/license pins, not evidence of a better routing algorithm. Extending Pin/Padstack from one convex shape per layer to a non-convex union is materially broader. |

## Smallest next falsifiable observation

Wait for the root's existing read-only padstack importer probe, preserving all failures. Only if it confirms the anticipated limitation, predeclare a separate no-routing import/contact experiment on the already exposed owned front/back controls. Keep exact original pin reference/number, center, layer, net and 0.3 mm anchor; add one exact same-net wiring polygon per target custom terminal in derived DSN only. Fix the added area; do not introduce a physical KiCad zone or synthetic pad. The narrow first experiment should import the whole DSN and inspect the actual in-memory board without saving/routing it.

Required observations before any solver experiment:

- One original logical pin remains for each native terminal; no fabricated net, subnet, pad number or duplicated terminal. The added area has the intended single net and exact signal layer. The pin center/anchor and body union equal native copper after placement/reflection/rounding.
- Body area, ordered/canonical contour and concave-notch membership match the observed polygon; no hull or lost lobe. Repeat the predeclared front and native-backside/270-degree DSN cases; these Y-symmetric shapes do not qualify arbitrary chiral reflections.
- Default obstacle-false is retained as an explicit negative configuration. A separately declared obstacle-true path must demonstrably block a foreign crossing and preserve same-net body contact using the actual search tree/clearance class. Measure effective flags, rather than infer them from argv or a setter return.
- Engine contact graph links anchor↔area↔valid remote same-net route; the false-hull capsule stays disconnected; foreign intrusion is rejected. Do not count any touched area as completion of every terminal on the net. Read `containsPlane` and require ordinary all-terminal connectivity for this scope.
- Source and final KiCad pad/footprint/zone/rule trees remain exact. If later SES includes area records, prove that route-only import discards only the synthetic representation and never duplicates or alters original copper. Preserve every added track/via and native semantic hash.

Existing ROOT native six-case controls are the oracle boundary, not tests of this area transport: paired front/back positives are 0 opens/0 blocking/4 warnings; hull-only landings have one exact open/0 blocking/5 warnings; foreign intrusions have the actual target copper short plus same-pair solder-mask companion (2 blocking/4 warnings). The first stricter six-case invocation remains failed; only the later predeclared v1.1 invocation passed its control predicates. `native-controls-basis.json` binds all six actual reports. No importer-only success replaces those native invalid/positive controls or final original-rule DRC.

Stop on failed identity, area geometry, resolution, foreign-clearance, reciprocal contact or all-terminal proof. Do not compensate by narrowing tracks, suppressing native checks, changing project class settings, or replacing custom copper in KiCad. If later route experiments are justified, charge export, observation, transformation, compilation if needed, routing, import and native finalization equally. An exact interchange repair belongs to B1; it supplies no C novelty or generalized superiority claim.
