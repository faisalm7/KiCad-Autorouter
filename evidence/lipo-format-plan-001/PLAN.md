## Separate four questions

1. **Dependency and redistribution closure remains incomplete.** Existing closure003/004 records establish the publisher CERN-OHL1.2 notice, pinned local logo/MIT library, and exact acquired bytes. The S2B model has an exact upstream Gregory Davill MIT2018 chain in research staging; retain that notice with arturo182 MIT2019 if later assembled. The hidden jumper model remains a dependency and its independent authorship is not established beyond the recorded repository notice. Stock footprint/symbol/3D versions remain unpinned; `${KICAD6_3DMODEL_DIR}` is an environment alias. Do not substitute installed libraries, rename aliases, install staged models into originals, or call the project complete. Native diagnosis using embedded board geometry does not close those gaps. These boards remain development-exposed and provisionally grouped for ancestry.
2. **Original-native settings are unobserved.** JSON Default preferences are width0.25, clearance0.2, via0.8/drill0.4mm. Original board minima include width approximately0.2, via approximately0.4, drill0.3 and annulus approximately0.05mm, with minimum clearance0.0. Record original decimal values and exact loaded integer units separately; do not assume floating JSON spells native values exactly. Preserve all severities, including `connection_width:ignore` and `padstack:warning`, and the empty exclusions. Run the current central critical-finding policy on raw native reports. The source's1mm tracks are reference geometry, not evidence of a new hard electrical width requirement; the task must not claim electrical suitability of a0.25mm replacement.
3. **Semantic migration is distinct from successful load.** Prefer preserving the old source shell and transferring only proven route/fill objects. The pinned parser supports `tstamp` and `uuid` aliases, but a global text rename is not a semantic proof. Native save can update layers, properties, defaults and fields. Retain both old and emitted boards and compare loaded semantic witnesses before considering conversion. Never alter the original version atom to bypass checks.
4. **Routing eligibility comes last.** A successful diagnostic is neither a complete dependency package nor accepted routing. The rounded outline independently excludes `placement-clearance-v1`; there are no placement areas requiring that policy. Floor policy additionally needs legacy pad/reference identity qualification. Prune/recovery paths assume UUID-oriented identities and remain unsupported until independently propagated. Do not make a global format allowlist change that silently opens them.

## Smallest proposed implementation boundary, after observations

Introduce a format-qualified item-ID reader that accepts exactly one valid `tstamp` **or** `uuid`, rejects dual/malformed/duplicate IDs, and compares normalized UUID values without rewriting source ASTs. First use it only for `pipeline.transplant_fill`: enforce a bijection of original and saved zones, and transfer derived fill fields only. Original zone intent, layers, outlines, pads, rules and protected routes remain exact invariants. Require actual old-source→modern-refill identity checks and imported route compatibility before granting this branch routing admission.

Keep numeric net mapping strict; do not fall back to guessed aliases. Preserve the original board version and complete project bytes. Use a distinct recorded source-format capability so an old-format success cannot imply general legacy or strategy support. If retaining the old shell cannot survive pinned native save/refill without changed semantics, stop and design a separately reviewed migration contract rather than relaxing immutable equality. Changes to floor `task_pads`, legacy `fp_text` reference handling, placement rules, thermal UUID indexing or generic fallback semantics are later scope, not this first extension.
