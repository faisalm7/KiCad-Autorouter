## Smallest code changes

1. **Separate the fixed input geometry policy from an explicitly bounded search contract.** `floor_route.receipt_policy` (58), `route` (288), `_route` (305), and `check_floor_result` (166) currently enforce placement + completion-only + default costs. That is intentional: do not merely remove these guards. Add one versioned experimental search-contract branch with a finite standard/tuned and named-cost set, using `pipeline.engine_profile_settings` (530). Keep existing schema-3 defaults and historical receipts unchanged. Every placement search must retain all three width-reduction prohibitions (`automatic_neckdown=false`, `fanout.enabled=false`, `neck_width_um=0`), the existing 20 µm planning margin, source/floor/area chain, and original native rules. Tuned runs must retain the existing observed optimizer-threshold audit. Do not expand saved preferences, layer masks, partial completion, protected routes, literal multi-class support, or other currently blocked geometry through this experiment.

2. **Give the shared validator a bound export basis.** Extend `pipeline.validate_candidate` (460), `floor_route.validate_contract` (129), and `final_context` (141) with an optional keyword such as `guidance_basis`, defaulting to the current job output. For C this points only to its own freshly accepted incumbent evidence, whose receipt and complete tree are frozen. Read the original native/export/floor contract there, but write each trial's fresh final context, refill, DRC, and metrics in that trial directory. Re-derive the original task and dimensions; never fabricate stage paths or copy a stale native-final audit onto a changed board. Keep the existing source, rule-area, immutable geometry, project-file, refill, native finding policy, and generated-route dimension checks mandatory.

3. **Add truthful pruning lineage readback, not an SES waiver.** `floor_route.audit_transport` (218) reconstructs a route result from SES/import/refill, and `check_floor_result` requires exactly eight routing stages. A pruned board deliberately cannot satisfy that reconstruction. In `strategy.prune` (227), bind each trial's parent candidate/hash, explicit eligible deletion IDs, and saved refill. Reconstruct `parent -> delete_routes -> refill polygons -> candidate`, with no other changes. Add a distinct versioned strategy receipt dispatch in `pipeline.check_result` (864): fully check the incumbent's ordinary placement routing receipt, audit the selected deletion ancestry, and reuse the shared final native/context/metrics checks for the delivered board. Keep every failed trial and its cost; failures cannot become ancestry. Missing strategy/policy fields or downgrade to schema 1 must fail when new artifacts are present. Do not loosen the ordinary SES reconstruction or its eight-stage requirement.

4. **Reuse proposals and quality selection.** Keep `zone_net_ids`, `proposals`, `delete_routes`, and bounded `feedback_proposal`: group then individual deletion, maximum 32 trials, 4–12 seconds per trial, feedback depth 2 and at most 8 extra routes. Selection uses generated candidates and zone membership, never original reference routing or a board/net-name whitelist. Fresh native acceptance, no worse length/vias, and no new warning identities remain required. Retain all 96 historical findings and every fresh raw report without suppression; future counts are measured, not hardcoded to 96. The current warning set loses duplicate multiplicity: add a focused duplicate-warning regression and use a multiset comparison for the new branch if “no new warning” includes duplicate findings. Native critical/unknown findings remain independently blocking.

5. **Use the newer lifecycle around the old strategy.** `strategy.cpu_used` currently sums supervisor CPU and registered steps; it lacks the newer waited-control-child accounting and scoped final-publication handling. Reuse `recovery.child_cpu/recover` and `floor_route.FloorJob/publish` patterns: one parent deadline and CPU remaining callback, no step double-counting, SIGINT/SIGTERM cleanup, bounded complete source/code/tool/receipt trees before and after publication, strict canonical readback, and invalidate canonical acceptance after a late change/cap/cancellation. Full completed-arm trees must be frozen once and never rebound after a failed freshness check. This is necessary for the new placement branch; do not claim a general legacy lifecycle repair without its controls.

## Frozen comparison to implement

Use a single fixed, sequential **B1-standard, B2-portfolio, C-feedback** comparison on the existing multichannel project selection. Extend the finite selector in `experiment_quality.PROJECTS/selected_source`; extend existing portfolio/paired contracts rather than create another runner. Historical completion-only evidence is feasibility context, not a fresh comparator. All three arms use the same original source, corrected placement/floor/both input policy, binaries and implementation.

| B1 | Fresh `standard`, default costs 50/5; native final validation. Keep the existing B1 label/profile meaning. |
| B2 | Existing `tuned` portfolio, fixed default 50/5 -> low 25/3 -> high 100/10. First attempt gets the remaining allowance minus the existing 15-second reserve. | C | Its own fresh **tuned/default** incumbent under the same first-attempt allocation rule as B2, then existing bounded feedback pruning and a fresh final native validation. Do not give C B1/B2's accepted candidate or use the historical board for free. If no accepted incumbent or no finalization budget remains, retain rejection. |

Freeze **120 seconds wall AND total CPU per arm**. Charge the entire measured shared setup/publication/checking overhead to EACH arm, retaining raw invocation cost separately. A practical common inner assignment is `120 - max(measured shared setup wall, shared setup CPU) - 5` seconds; freeze this formula and the 5-second wrapper reserve, and give the same assignment to all three. B2/C retain their internal 15-second planning reserve; engine settings still withhold their existing 30-second grace and 10-second native reserve. Reservations do not increase the cap or guarantee success. Count source intake, all failed trials, control subprocesses, final validation, readback and publication. Crossing the final charged cap invalidates the comparison; no saved incumbent exemption.

Compare C to B1 and **every accepted B2 frontier point**. Report completion first, then native length/vias only when both deliveries are accepted. Record C's incumbent-to-final change as the local pruning observation. Different use of remaining budget is explicit: tuned restarts versus native pruning. A local Pareto gain would support this postprocessing result on an exposed board; it would not establish a new routing algorithm, generalized completion gain, or an independent family result. No new data split or population denominator is created here.

## Required controls and largest risk

Before the three fresh arms: an owned placement/floor-compatible zone fixture must pass ordinary standard/tuned routing and a redundant-route deletion with fresh refill/DRC; a deliberately necessary-route deletion must fail connectivity. Pure controls must reject stale parent/deletion lineage, wrong eligible net/protected deletion, rehashed floor/rules/report tampering, policy downgrade, failed-trial omission/double-counting, duplicate warning additions, and final publication signal/cap/staleness. Keep existing legacy accepted receipts readable. These controls qualify the new paths; mocks alone do not qualify native pruning.

The largest correctness risk is **making the changed candidate look like an ordinary placement SES result, or falling back to native-only validation to avoid its transport check**. The export-basis and explicit deletion/refill ancestry changes above address that risk without duplicating the floor/native validator. The strongest measurement risk is calling an old completion-only result B1 or calling deterministic reruns a tuned B2; the fixed fresh profiles above avoid both.

All observations here are finite local byte-consistency checks, not authentication or concurrent-writer safety. No production files were changed and no native/JVM/network/Git command or test suite was run.
