# Legacy zone severity: historical meaning and smallest next check

`zone_has_empty_net` meant that an assigned copper-zone net had no pads. It did **not** mean an empty net label. At pinned KiCad6.0.0 (`7545e2dfee8f86d155723e049501fb7c3f497e10`), the registry binds that key to its zone-pad-count diagnostic ([drc_item.cpp:81–83](https://github.com/KiCad/kicad-source-mirror/blob/7545e2dfee8f86d155723e049501fb7c3f497e10/pcbnew/drc/drc_item.cpp#L81)). This is a demonstrated historical origin/version, not a claim to have found the introducing commit.

The actual provider rebuilds connectivity, then visits `board->Zones()` on copper. Its violation predicate is `netcode < 0 || (netcode > 0 && GetPadCount(netcode) == 0)`. Netcode0 is deliberately exempt. It reports the zone UUID/item, not a missing pad pair. It has no same-layer/contact-to-zone requirement and is not the thermal-relief or unconnected-items test. [Provider setup:80–86](https://github.com/KiCad/kicad-source-mirror/blob/7545e2dfee8f86d155723e049501fb7c3f497e10/pcbnew/drc/drc_test_provider_connectivity.cpp#L80), [zone predicate:120–143](https://github.com/KiCad/kicad-source-mirror/blob/7545e2dfee8f86d155723e049501fb7c3f497e10/pcbnew/drc/drc_test_provider_connectivity.cpp#L120).

`GetPadCount` counts valid connectivity items whose parent type is PCB_PAD_T and whose assigned net code matches. Counting arbitrary pad S-expressions alone is therefore not established as identical. The implementation remains the same in pinned10.0.0, and the installed wrapper declares `CONNECTIVITY_DATA.Build(board)->bool` and `GetPadCount(net)->unsigned int`. Current Build reconstructs the algorithm/item inventory rather than assuming a prior LoadBoard call initialized it. These APIs are source/declaration evidence, not newly executed calls. [6.0 count:577–592](https://github.com/KiCad/kicad-source-mirror/blob/7545e2dfee8f86d155723e049501fb7c3f497e10/pcbnew/connectivity/connectivity_data.cpp#L577), [10.0 count:727–743](https://github.com/KiCad/kicad-source-mirror/blob/0feeca2a807f428ad2b3fa7c1e39625cb769f02c/pcbnew/connectivity/connectivity_data.cpp#L727), [10.0 rebuild:104–145](https://github.com/KiCad/kicad-source-mirror/blob/0feeca2a807f428ad2b3fa7c1e39625cb769f02c/pcbnew/connectivity/connectivity_data.cpp#L104).

The smallest next actual qualification is three owned two-layer fixtures, using complete unchanged original project/rule bytes and the existing bounded observation+original-rule DRC controller; no engine or source-board rerun is required:

1. Positive: an ordinary board-level copper zone assigned to a declared net with one ordinary copper pad on that net. Record successful native connectivity Build, exact zone UUID/copper status/layers/net code/name, pad identities and GetPadCount>=1; historical guard passes. Native DRC remains separately authoritative.
2. Negative: identical owned pad/zone geometry, but the zone is assigned to a declared different net with no pads. Record GetPadCount0 and reject independently even if native10 emits no legacy diagnostic. Never label this as native10 producing the removed finding.
3. Semantic contrast: zone netcode0. Record the historical predicate as nonviolating without calling count for0, preserving all native findings. This proves the guard is not a guessed “nonempty name” rule; it does not itself admit netless-zone routing.

Build/zone/count return types must be primitive and bound to the same loaded board, with original source/project hashes, full UUID/net identity comparison and raw report retained. A failed build, missing zone/pad census, negative/malformed/unknown net assignment or unsupported zone intent is unsupported. Begin with ordinary board-level copper zones and ordinary pads; keep footprint rule areas and other unfamiliar semantics blocked. Do not count tracks/vias as pad substitutes. Reuse the existing same-load observer and shared DRC/capture/budget helper; do not create a second routing or validation framework.

If those controls qualify the loaded-board count/zone mapping, a narrow future compatibility guard can independently reject exactly the historical condition before/after validation and rederive it in result readback, while retaining the original severity bytes. An initial compatibility path should be scoped to the literal `error` setting; other values remain unsupported pending an explicit policy decision. Until then the current unknown-key gate stays. A single PAW clean report is insufficient, and this research recommends no generic severity whitelist or silent ignore.
