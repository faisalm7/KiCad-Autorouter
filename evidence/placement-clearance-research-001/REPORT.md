# Rounded-pad export clearance diagnosis

The two actual native clearance errors are explained by a saved DSN polygon that locally understates the original rounded copper by approximately 2.235 µm. Both routed tracks have more than 0.300 mm clearance to that exported polygon while violating the original 0.300 mm copper clearance. This is adapter geometry approximation evidence, not C novelty or a new accepted routing result.

Inputs are the completed, rejected placement arm in `.runs/placement-routing-pair-001/arm-1`. `analysis.json` binds original project files, candidate, final native report, raw/engine DSN, rule guidance and analysis/parser code. All watched bytes were unchanged. No native tools or engines ran in this task. Sources and outputs remain immutable; only this ignored research directory was written.

These identifiers locate the diagnosis only; no proposed production policy should target them.

The analysis represents the exact original roundrect as its rectangular core plus a disk of radius 0.750 mm, computes segment-to-core distance minus pad radius and half track width, then independently computes segment-to-every-saved-polygon-edge distance minus half width. DSN placement/pin coordinates select and transform the same padstack. Its raw polygon and final engine-task polygon are exactly equal. The selected 32-vertex saved polygon is simple and strictly convex; its maximum edge support inward deficit is 2.235580 µm. This is a local saved-polygon measurement, not a generic filled-board topology claim.

## Pinned source mechanism

All cited KiCad source is tag 10.0.0, commit `0feeca2a807f428ad2b3fa7c1e39625cb769f02c`, matching the pinned installed tool's source tag. SHA receipts preserve copied older research sources and newly fetched files. Relevant code is GPL-2.0-or-later as stated in file headers; original headers and LICENSE.README are retained, ignored, and not being promoted as project-owned code.

- [`specctra_export.cpp`, lines 468–494](https://github.com/KiCad/kicad-source-mirror/blob/0feeca2a807f428ad2b3fa7c1e39625cb769f02c/pcbnew/specctra_import_export/specctra_export.cpp#L468) expands the radius and dimensions using a fixed 36-segment compensation, then passes the original pad's `GetMaxError()` to the actual polygon routine with `ERROR_INSIDE`. The compensation and actual segmentation are therefore selected by different mechanisms.
- [`convert_basic_shapes_to_polygon.cpp`, lines 292–360](https://github.com/KiCad/kicad-source-mirror/blob/0feeca2a807f428ad2b3fa7c1e39625cb769f02c/libs/kimath/src/convert_basic_shapes_to_polygon.cpp#L292) chooses at least 16 full-circle segments from radius/error, uses shortened symmetric first/last quarter-arc chords, and emits inside-approximation vertices. The roundrect wrapper at lines 459–526 delegates to it.
- [`geometry_utils.cpp`, lines 42–64](https://github.com/KiCad/kicad-source-mirror/blob/0feeca2a807f428ad2b3fa7c1e39625cb769f02c/libs/kimath/src/geometry/geometry_utils.cpp#L42) calculates the ideal count from sagitta and uses nearest-integer rounding, not a ceiling. Thus a project `max_error=5 µm` is not itself a rigorous 5 µm upper bound on every resulting chord.
- [`pad.cpp`, lines 1167–1240](https://github.com/KiCad/kicad-source-mirror/blob/0feeca2a807f428ad2b3fa7c1e39625cb769f02c/pcbnew/pad.cpp#L1167) builds the effective native roundrect from the core rectangle and exact-radius thick segments, rather than using the DSN inside polygon.

For the 0.750 mm radius, the exporter adds round(750000 × (1−cos(π/36))) = 2854 nm. Actual segmentation of the 752854 nm expanded radius at 5000 nm max error yields 27 full-circle segments and 13⅓° long chords. Their ideal sagitta is 5090.529 nm. Subtracting the 2854 nm compensation leaves 2236.529 nm inward error before integer/printed-coordinate effects, agreeing closely with the directly measured saved polygon. The mismatch is substantially larger than a single 0.1 µm DSN resolution step.

## Scope of a 20 µm engine-only margin

Original source census: 327 pads, comprising 35 roundrect, 219 rectangle and 73 circle pads. Raw DSN padstack shapes comprise four polygons (two geometries × two layers), eight circles and six rectangles. The second roundrect geometry is 4.3 × 1.7 mm, radius 0.850 mm, ratio 0.5. The same source formula yields 3235 nm compensation, 29 segments and an estimated remaining inward deficit of 1766.700 nm. Formula estimates with an explicitly declared 2 nm generation plus 10 nm printed-vertex allowance remain below 2.25 µm for both shapes. Those allowances are estimates, not a newly qualified universal bound.

The proposed fixed additive **20 µm** margin is consequently conservative relative to the identified chord defect, even allowing two such shape deficits. It is a defensible prospective adapter experiment. It must be described as an experimental safety margin, not “two rigorously bounded 5 µm errors”: the source rounds segment count, and the complete numerical chain through DSN placement/serialization, Freerouting geometry and SES import has not been independently bounded. The second, fully rounded shape also has tiny near-coincident/crossing-looking serialization details at its collapsed rectangular core (at the nanometre scale); this task does not certify their polygon interpretation. Circle pad exports use a circle primitive, avoiding this particular chord approximation, but that is not proof of every engine representation downstream. No claim that 20 µm covers all possible board geometry, arbitrary units, offsets, noncardinal rotations, custom pads or future tool versions follows.

The margin should be additive only to the three already-audited engine-task clearance atoms (structure generic, structure SMD-SMD and class clearance). For this board each derived clearance becomes 0.320 mm. Preserve exact widths, vias, nets, padstacks, zones, keepouts, all original rule files/severities and final native constraints. A new explicit diagnostic policy/receipt must state the additional bias: the existing floor-v1 contract requires exact derived values and must not silently accept changed DSN bytes. Refuse missing/extra/ambiguous clearance atoms, wrong units, negative margins, repeated application and unqualified classes. Reconstruct the transformation and retain every intermediate DSN.
