# Try the local experimental candidate

**Runtime094 is the current candidate tested on this Mac.** Its [Native/CLI delivery](evidence/runtime094-licensed-placement-delivery-001.json) and [actual GUI118 finite workflow](evidence/runtime094-GUI118-core-001.json) include automatic selected-component placement, protected routing, review, explicit intent, fresh separate export and checked PCB opening. Core tools need no AI account. This narrow development demonstration does not establish broad engineering usefulness, independent installation or Windows Native support.

The existing installation is `.runs/runtime094 fresh install 001`, source `3113cca4c41851c54daf77b2fcb465179ff53e99`, manifest `813d42c6847fc7e78c81c45738074107209ff02fcc8c9b9e480db6e681650ea1`. It uses isolated KiCad10.0.7 and pinned existing dependencies. Do not reinstall or repeat completed qualification merely to resume. The earlier 088 group and 091/092 CLI results retain their own scope in [STATUS](STATUS.md).

1. Use the existing assistant if it is already open. Before starting another session, close test assistants and KiCad editors/managers normally. The prepared Finder launcher is:

   ```sh
   './.runs/runtime094 fresh install 001/.runs/gui-session118/Launch Design Assistant GUI118 Edge.command'
   ```

   Finder startup and the actual toolbar were observed. This is an owned demonstration launcher on the same Mac/account, not a standalone or clean-OS installation. Its configuration/PCM root is isolated; it refuses a competing KiCad instance and does not change personal plugins or browser settings.

2. Open `.runs/gui-session118/inspection/PushButtonLed.kicad_pro` within that installation, then **Tools → PCB Editor**. Click the small green trace icon beside `>_`. The assistant opens separately. Choose the exact saved PCB explicitly: this demonstration uses `.runs/gui-session118/source/PushButtonLed.kicad_pcb`, with `.runs/gui-session118/jobs` as its output folder. The inspection project is a separate copy. Source/editor identity is not inferred from an unsaved buffer. Close the inspection PCB before validation and keep authoritative source editors closed.
3. Choose **Place components… → Inspect project** and read the original findings. For this licensed R1/R2 demonstration, load `.runs/gui-session118/placement-settings-gui118.json`. It contains the reviewed selection/rectangle, explicit affected-net rebuilding and 13 protected route UUIDs. Current support keeps orientation/side fixed. The selected-source-baseline scope admits unchanged inherited proximity only after source Native checks; every changed pose must pass the moving checks. This scope does not support rigid groups. The [earlier 088 group demonstration](evidence/runtime088-GUI114-core-001.json) is separate evidence for its supported scope.
4. Choose **Find placement alternatives**, inspect the first proposed arrangement and its copper-rebuild plan, and edit allowed coordinates if needed. The search may return no changed alternative. Invalid edits refuse without replacing the previous pose. A changed draft is labelled **Edited draft**. Choosing a real alternative revokes its prior validation. A draft is not a validated board. Explicitly review the exact draft, acknowledge the saved/closed source and choose **Validate placement**. KiCad runs outside the editor on a separate copy; **Cancel** revokes positive state.
5. Open **Routing settings** after placement validation. Review exact selected nets, protection, supported layers, preferences and budget. The demonstration uses 90 seconds for routing, completion-only/both/native/all source layers and default scoring. Routing can also be used directly: **Finish gaps** preserves all existing routes; whole routing preserves locked copper. General selected-net/layer combinations remain limited; unsupported inputs refuse.
6. Preview, Route and Create review. Inspect both copper layers and every finding in **Microsoft Edge**, then choose **Accept intent** or **Reject intent**. Acceptance records software/user intent, not PCB certification. **Fresh export** performs new original-rule Native validation with its separately disclosed budget. **Open checked export** checks the exact current evidence before opening the separate project. Never overwrite an open source board.

Original projects remain unchanged. Native checks, rules, connectivity, protected copper and stale/cancellation refusal remain mandatory.
